# TicBox

[English](README.md) | 简体中文

TicBox 是 TicWatch 手表（TicWatch Pro 5、Pro 5 Enduro、Atlas）的本地优先手机伴侣应用，可以替代官方的 Mobvoi Health 手机端，并附带一套手机–手表工具箱。

默认数据流是 **手表 → 本地蓝牙 → 手机 → 本地数据库**。Mobvoi 云、Google 云和手表上网代理默认关闭，只有你在应用里明确开启后才使用。

## 功能

| 功能 | 需要什么 |
|---|---|
| 通知同步：手机通知显示在手表上，可以点通知里的按钮、用文字回复 | 配对，并授予通知使用权 |
| 通话控制、媒体控制 | 配对 |
| 表盘管理、手表偏好设置、锁屏、手表应用 | 配对 |
| 紧急求助（SOS）、手表找手机 | 配对 |
| 手机找手表、勿扰同步 | [本地桥接](#第-5-步安装本地桥接读取健康数据) |
| 健康数据：心率、睡眠、血氧、步数等记录保存在手机上，并绘制图表 | 本地桥接 |
| 手机数据的导出与导入 | 无 |
| 高级工具：给手表装应用（含分包和数据包）、应用管理、文件管理、剪贴板、终端、远程屏幕 | 手表的无线调试，或 root |
| 完整训练记录、GPS 路线和逐点数据 | [root](#进阶root-与手表模块) |
| 健康变更日志：同步时只读取变化的部分 | root |
| 更多健康监测设置、按应用设置通知的声音和振动 | root 和手表模块 |

和官方应用相比尚未实现或受限制的功能，见[能力差距](docs/dev/capability-gaps.md)。

## 准备

- **手表**：TicWatch Pro 5、Pro 5 Enduro 或 Atlas。Atlas 出厂就是 Wear OS 4；Pro 5 和 Pro 5 Enduro 出厂是 Wear OS 3.5，官方已经推送了 Wear OS 4 升级，没收到的话可以在手表的 Settings → System → System updates 手动检查。Wear OS 3.5 也能正常使用 TicBox，只是换手机时没法保留手表上的数据。
- **手机**：Android 14 及以上，有蓝牙和 Wi-Fi。
- **Wi-Fi**：手机和手表能连上同一个 Wi-Fi。手机通过手表的无线调试安装本地桥接、使用高级工具，所以手表不需要用线连电脑；手表附带的两触点充电线本来也不能传数据。
- **电脑（可选）**：只在手机上没法直接安装 App 时才需要，用数据线连接的是手机，见[用电脑安装](#用电脑安装可选)。

一块手表同一时间只能和一部手机配对。手表现在如果和别的手机（或 Mobvoi Health）配着对，请看[第 2 步：让手表进入配对状态](#第-2-步让手表进入配对状态)。

## 新手教程

每一步按顺序做一次即可。TicBox 的按钮名以简体中文界面为准；手机系统的菜单因品牌和版本可能略有不同。手表的菜单按英文界面写，手表用中文时是对应的中文名称。

### 第 1 步：下载并安装手机 App

1. 用手机浏览器打开本项目的 [Releases](https://github.com/doragonRider/TicBox/releases) 页面，下载最新版本里的 `ticbox-phone-<版本>-release-<commit>.apk`。只需要这一个文件：手表上的组件已经包含在手机 App 里。同一页的 `SHA256SUMS.txt` 可以用来核对文件是否完整。
2. 在浏览器的下载列表或文件管理器里点开这个文件。第一次会提示不允许安装未知应用：点“设置”，为浏览器（或文件管理器）打开“允许来自此来源的应用”，返回后点“安装”。手机自带的安全检测弹出提示时，选择继续安装。
3. 装好后打开 TicBox。

想先看看界面，可以在 App 首页点“试用演示手表”。它用示例数据演示各个页面，不连接真的手表；只有“高级”里的工具会通过无线调试操作真实设备。

**安装被拦截时：**

- **提示“App blocked to protect your device”，只能点“Got it”**：这是 Google Play 保护机制在拦截申请了通知使用权、又不是从应用商店安装的应用。可以暂时关掉扫描：打开 Play 商店，点右上角的头像 →“Play 保护机制”→ 右上角的设置图标，关闭“使用 Play 保护机制扫描应用”，回去重新安装。装好后记得把它重新打开。
- **巴西、印度尼西亚、新加坡和泰国的手机**：从 2026 年 9 月 30 日起，Android 会拦截没有在开发者验证中登记的开发者的应用，TicBox 就是这种情况；2027 年起会扩大到其他地区。可以在手机的开发者选项里打开“Allow apps from unverified developers”（允许安装未验证开发者的应用）：第一次打开要等 24 小时，之后可以选开启 7 天或一直开启。这个选项正在逐步推送，你的手机上可能还没有。
- 上面的办法都不行时，可以用电脑安装。这两种拦截都不适用于电脑的 ADB 安装。

#### 用电脑安装（可选）

需要一台电脑（Windows、macOS 或 Linux）和一根能连接手机、能传数据的 USB 线，只能充电的线不行。

1. 下载 Google 的 [SDK Platform-Tools](https://developer.android.com/tools/releases/platform-tools)，解压到一个好找的文件夹，例如 `D:\platform-tools`，并把下载的 APK 也放进去。
2. 在这个文件夹里打开终端：Windows 上在文件夹空白处点右键，选“在终端中打开”；macOS 和 Linux 打开“终端”后用 `cd` 进入该文件夹。运行下面的命令，能看到版本号就说明 ADB 可以用了：

   ```bash
   ./adb version
   ```

   Windows 的命令提示符（cmd）里写成 `adb version`，不带 `./`。下文的命令同理。

3. 在手机上打开开发者选项：进入“设置 → 关于手机”，连续点按“版本号”七次。再在“开发者选项”里打开“USB 调试”。部分品牌（如小米）还要打开“USB 安装”。
4. 用 USB 线连接电脑，手机上弹出“允许 USB 调试吗？”时点“允许”。确认手机已连接，列表里应出现一行 `device`：

   ```bash
   ./adb devices
   ```

5. 安装：

   ```bash
   ./adb install -r ticbox-phone-<版本>-release-<commit>.apk
   ```

   看到 `Success` 就装好了，可以拔掉 USB 线。`-r` 表示覆盖安装、保留数据，以后更新也可以用这条命令。

### 第 2 步：让手表进入配对状态

先看一下手表的 Wear OS 版本，它是 Settings → System → About 里的第一项。再按手表现在的情况选一种做法：

| 手表现在 | 做法 |
|---|---|
| 新手表，或已经恢复出厂 | 开机选好语言，停在提示用手机配对的界面，然后继续[第 3 步：配对](#第-3-步配对) |
| 连着另一部手机，Wear OS 4 | [用“转移”换到这部手机](#用转移换到这部手机)，手表上的数据都保留 |
| 连着另一部手机，Wear OS 3.5 | Wear OS 3.5 不能保留数据换手机。先在手表的 Settings → System → System updates 升级到 Wear OS 4，再转移 |
| 连着这部手机上的 Mobvoi Health | 见[同一部手机换用 TicBox](#同一部手机换用-ticbox) |

重置会清除手表上的全部数据，只作为[最后的手段](#重置最后的手段)。手表上的 Settings → System → Disconnect & reset 会重置手表。

#### 用“转移”换到这部手机

需要 Wear OS 4。让手表和原来的手机保持连接，电量充足。转移完成之前，不要在原来的手机上解除配对，也不要在它的系统蓝牙设置里忘记手表。

转移要在手表上打开转移确认页。在这部手机上用 TicBox 的演示手表就能打开：演示手表的“高级”工具通过无线调试操作的是真实的手表。手表不需要登录 Google 帐号。

1. 在手表上连好 Wi-Fi、打开无线调试，做法和[第 5 步](#第-5-步安装本地桥接读取健康数据)“在手表上”的 1–3 相同。
2. 在 TicBox 首页点“试用演示手表”，进入“手表 → 管理 → 高级 → 无线调试”，和手表配对并连接，做法和[第 5 步](#第-5-步安装本地桥接读取健康数据)的 5–6 相同。
3. 返回“高级”，打开“终端”，输入下面这行并回车：

   ```bash
   am start -W -a android.settings.WATCH_TRANSFER
   ```

4. 在手表上确认，手表进入转移模式，等待新手机。
5. 回到 TicBox 点“退出演示”，然后继续[第 3 步：配对](#第-3-步配对)，按 TicBox 的提示完成。手表回到表盘，就转移好了。

也可以在电脑上做同样的事：用 `./adb pair` 和 `./adb connect` 连上手表的无线调试，再运行 `./adb shell am start -W -a android.settings.WATCH_TRANSFER`。这样不需要数据线。

转移之后，手表可能在某次断开后不再接受连接，例如更新 TicBox 之后。TicBox 一直显示在重连时，正常重启一次手表即可恢复，不需要重置，也不需要删除配对。这是手表系统的已知问题，在转移完成前就删掉旧手机的配对时更容易出现。

#### 同一部手机换用 TicBox

Mobvoi Health 和 TicBox 装在同一部手机上时，不能直接转移：转移要求新旧是两部不同的手机，同一部手机做转移会把这块手表的蓝牙配对删掉。

想保留手表上的数据，可以借另一部 Android 14 及以上的手机中转。这条路还没有在真机上验证过。

1. 在另一部手机上按[第 1 步](#第-1-步下载并安装手机-app)装好 TicBox，用上面的“转移”把手表从 Mobvoi Health 换到那部手机。完成后，可以卸载这部手机上的 Mobvoi Health。
2. 在那部手机的 TicBox 里打开“手表 → 管理 → 连接 → 更换绑定的手机”，点“检查手表支持情况”，再点“在手表上打开迁移流程”，在手表上确认。
3. 在这部手机的 TicBox 上按[第 3 步：配对](#第-3-步配对)把手表配对回来。
4. 转回来以后，在那部手机的同一页点“清除这部手机的配对记录”。

#### 重置（最后的手段）

在手表上选择 Settings → System → Disconnect & reset。手表重启后选好语言，然后继续[第 3 步：配对](#第-3-步配对)。手表上的全部数据都会清除，包括还没同步出去的健康记录。重置之前，尽量把数据留在别处：

- 用过 Mobvoi 帐号的话，云端可能存有健康记录：之后可以在 TicBox 的“设置 → Mobvoi 账号”登录同一个帐号，把云端的健康记录下载到手机。这项默认关闭，会联网，还没有在真实帐号上完整验证过。
- 用 TicBox 的，在“设置 → 数据迁移”导出，到新手机上导入。

### 第 3 步：配对

1. 在手机上打开系统的“位置信息”总开关。系统在配对时靠它找到手表，并不会因此给 TicBox 定位权限。
2. 打开 TicBox，点“添加手表”，按提示允许“附近的设备”权限，打开蓝牙。
3. 让手表靠近手机，在 Android 弹出的列表里选择你的 TicWatch。
4. 手机和手表上会显示同一个配对码，两边都确认。
5. 接着进入“设置手表”：阅读并勾选“我已阅读并接受条款”，然后继续。
   - Google 帐号转移会跳过，之后可以在手表上自己添加帐号。
   - “Google 设备检查”默认不勾选，勾选后会用到手表的网络；不需要就保持不勾选。
6. 看到“手表已就绪”就完成了，手表上会显示已连接手机。

之后 TicBox 会在后台自动保持连接，不需要一直开着。如果手机会自动清理后台应用，请在系统设置里允许 TicBox 后台运行。

### 第 4 步：打开通知同步

1. 在“手表”页点“通知”，再点“授予权限”，在系统页面里为 TicBox 打开通知使用权。
2. 如果开关是灰色的、点不动（在手机上直接安装的 App 通常会这样）：打开 TicBox 的“应用信息”，点右上角 ⋮ →“允许受限制的设置”，再回去打开。

在同一页可以按应用选择哪些通知发到手表。

### 第 5 步：安装本地桥接（读取健康数据）

手表记录的健康数据，要通过手表上的“本地桥接”传到手机。它已经包含在手机 App 里，由手机通过手表的无线调试来安装，不需要电脑。本地桥接在手表上没有联网权限，只通过蓝牙和这部手机通信。

**在手表上：**

1. 连上 Wi-Fi，和手机用同一个网络。
2. 打开开发者选项：进入 Settings → System → About → Versions，连续点按 Build number 七次。
3. 进入 Settings → Developer options，打开 ADB debugging 和 Wireless debugging。手表询问是否允许在这个网络上调试时，点允许。

**在手机上：**

4. 打开“健康”页，点顶部提示里的“去设置”，进入“本地桥接”页。也可以从“手表 → 管理 → 高级 → 本地桥接”进入。
5. 点“打开无线调试”。这时在手表的 Wireless debugging 里点用配对码配对设备的选项，手表会显示六位配对码，保持这个页面开着。
6. 回到手机，在“在此 Wi-Fi 上找到”里点“可配对”的那一项，输入手表上的六位配对码，点“配对”。配对后再点“可连接”的那一项，显示“已连接”即可。
7. 返回“本地桥接”页，点“安装”，等它装好。

**再回到手表：**

8. 在手表的应用列表里打开“本地桥接”，打开“允许手机读取”。如果出现“授予蓝牙权限”，也点一下。

回到手机的“本地桥接”页，几项都显示完成就可以了。新装的本地桥接在打开“允许手机读取”之前不会响应手机，这是正常的。

装好以后，日常使用不需要无线调试，可以把它关掉；以后更新本地桥接时再打开。

### 第 6 步：同步健康数据

1. 打开“健康”页，点“从手表同步”。之后手表连上、或者重新打开 App 时也会自动同步。
2. 为了让第一次同步快一些，只读取最近 3 天的明细。手表上还有更早的数据时，页面会给出提示，点“全部同步”即可，可能需要几分钟。

以后想完整重读一遍，可以用“设置 → 诊断 → 立即全量同步数据库”。

## 日常使用

- **手表页**：表盘、通知；“管理”里有手表偏好设置（含勿扰同步、手表应用、锁屏、健康监测）、查找设备、媒体控制、通话、紧急求助、高级工具和连接。
- **健康页**：各项数据的图表和明细、训练记录。
- **设置页**：隐私、外观、语言、数据迁移（导出和导入手机数据）、诊断，以及默认关闭的 Mobvoi 帐号和云服务。
- 紧急求助、通话等功能第一次打开时，页面会说明需要哪些权限。
- **勿扰同步**：在“手表偏好设置”里选择“跟随手机”。它需要[第 4 步](#第-4-步打开通知同步)打开的通知使用权，第一次使用还要通过无线调试为本地桥接授权一次，按页面提示操作。

### 换手机

手表要求 Wear OS 4。旧手机上的 TicBox 负责开始转移，手机上的数据用导出和导入带走。

1. **旧手机**：在“设置 → 数据迁移”里导出，“手表配对身份”保持不勾选，把文件传到新手机。
2. **新手机**：按[第 1 步](#第-1-步下载并安装手机-app)装好 TicBox，在“设置 → 数据迁移”里选择这个文件，点“导入并重启”。
3. **旧手机**：打开“手表 → 管理 → 连接 → 更换绑定的手机”，点“检查手表支持情况”，再点“在手表上打开迁移流程”，在手表上确认。
4. **新手机**：按[第 3 步](#第-3-步配对)配对，再按[第 4 步](#第-4-步打开通知同步)重新授予通知使用权。其他权限也是按手机记录的，用到时按页面提示重新授予。之后打开“本地桥接”页检查一下。
5. **旧手机**：手表和新手机连接稳定、健康同步也恢复以后，在“更换绑定的手机”页点“清除这部手机的配对记录”。

转移之后如果手表连不上，同样重启一次手表。

### 更新

1. **手机**：下载新版 APK，像[第 1 步](#第-1-步下载并安装手机-app)一样点开安装，数据保留。Play 保护机制可能提示“App scan recommended”：可以点“Scan app”扫描后安装，大约要半分钟；也可以点“More details”→“Install without scanning”直接安装。用电脑的话运行 `adb install -r`。
2. **手表**：打开手机的“本地桥接”页，按提示更新。和[第 5 步](#第-5-步安装本地桥接读取健康数据)一样，需要手表的无线调试已连接；有 root 的话可以直接更新，见下文。

每个版本的[更新说明](docs/releases/)会写明要更新手机、手表还是两边都要。两边之间的私有协议有变化时，只更新一边会让高级工具拒绝连接，所以拿不准时两边都更新。

### 常见问题

| 现象 | 处理 |
|---|---|
| 手机上安装 APK 被拦截 | 见[第 1 步](#第-1-步下载并安装手机-app)的“安装被拦截时” |
| 用电脑安装时，`adb devices` 里没有手机，或显示 `unauthorized` | 换一根能传数据的 USB 线，在手机上点“允许 USB 调试” |
| 用电脑安装时提示 `INSTALL_FAILED_USER_RESTRICTED` | 在开发者选项里打开“USB 安装”（小米等品牌） |
| 配对时列表里找不到手表 | 打开手机的“位置信息”总开关，确认手表停在配对界面、离手机不远 |
| 通知使用权的开关是灰色的 | 应用信息 → ⋮ →“允许受限制的设置” |
| 无线调试找不到手表 | 两台设备连同一个 Wi-Fi，手表保持在 Wireless debugging 页面，然后点“重新搜索”；Android 17 的手机还要允许访问本地网络中的设备 |
| 本地桥接页显示没有响应 | 在手表上打开本地桥接，开启“允许手机读取”，再点“再次检查” |
| 健康数据只有最近几天 | 在健康页点“全部同步” |

## 进阶：root 与手表模块

这一部分完全可选，前面的功能都不需要 root。

**前提**：手表已经装好 [Magisk](https://topjohnwu.github.io/Magisk/) 26 或更高版本。本文不介绍如何给手表解锁、刷入 Magisk：这通常会清除手表数据、影响保修，操作不当可能让手表无法开机，风险请自行判断。

root 后可以多做这些：

| 功能 | 需要 | 在哪里 |
|---|---|---|
| 完整训练记录、GPS 路线、圈和逐点数据 | root | 手表上的本地桥接 |
| 不用无线调试就能用高级工具，并通过 root 更新本地桥接 | root | 手表 → 管理 → 高级 → 本地桥接（root） |
| 健康变更日志：同步时只读取变化的部分 | root | 手机的本地桥接页 → 健康变更日志 |
| 更多健康监测设置（共 34 项，其中 16 项需要模块） | root 和手表模块 | 手表 → 管理 → 手表偏好设置 → 健康监测 |
| 按应用设置通知的声音和振动（没有模块时，手表对每条通知都会响铃并振动） | root 和手表模块 | 手表 → 通知 → 声音和振动控制 |

### 1. 打开 root 读取

1. 在手表上打开“本地桥接”，打开“读取完整运动记录（root）”。
2. 手表弹出 Magisk 的授权提示时，点允许。

这一步也是后面几节的前提。之后手机同步时会多出训练、GPS 路线和逐点明细，在“健康”页的训练记录里查看。它只在本地桥接的私有目录里建一个临时快照，读完就删除，不修改官方的运动记录。关掉这个开关不影响普通的健康读取。

### 2. 通过 root 使用高级工具

在“手表 → 管理 → 高级”里选择“本地桥接（root）”，手机会经蓝牙以 root 连接手表上的工具，不再需要无线调试。本地桥接自己的更新也可以走这条连接。

### 3. 安装手表模块

手表模块（Magisk 模块 `ticwatch_health_settings`）同样包含在手机 App 里，不用另外下载。它加载进手表的官方健康应用和系统界面，提供更多健康设置和按应用的通知提醒。

1. 在手机上进入“手表 → 管理 → 连接 → 手表模块”，也可以从“通知 → 声音和振动控制”进入。
2. 页面会逐项检查手表连接、模块、Zygisk 和健康应用。需要按应用设置通知提醒的话，先打开“通知声音和振动控制”开关。
3. 点主按钮，例如“安装并重启手表”。确认后它一次做完缺少的步骤：安装或更新模块、在 Magisk 里开启 Zygisk、重启手表。
4. 手表大约一分钟后自动连回来，页面会确认模块已经加载。

注意：

- 安装时尽量让手表保持亮屏，熄屏休眠可能让安装停住。
- 如果页面提示健康应用在 Magisk 的排除列表（DenyList）里，请在 Magisk 里把它移出，否则模块不会加载。
- 模块只适配特定版本的官方应用和手表系统；不适配时页面会说明，手表照原来的方式工作。

### 4. 健康变更日志

开启后，同步时只读取变化的部分，不用每次扫描整张表。

1. 在手机的“本地桥接”页点“健康变更日志”。
2. 分别为“健康数据”和“运动记录”打开开关。
3. 阅读确认弹窗后开启。它会在手表健康应用的数据库里添加触发器，不会改动健康数值；万一日志写入失败，健康应用自己的这次写入也可能失败。开启后的第一次同步会完整读取一遍。

随时可以在同一页把它移除。装了手表模块时，健康数据的日志改经模块读取，速度更快；没装模块也能用。

### 5. 停用和卸载

- **手表模块**：在手表的 Magisk 里停用或移除 `ticwatch_health_settings`，然后正常重启。已经保存的健康和闹钟设置属于官方应用，不会回滚。
- **健康变更日志**：在“健康变更日志”页关闭。移除模块不会删除它。
- **root 读取**：在手表的本地桥接里关掉“读取完整运动记录（root）”。

实现细节见[手表组件](docs/dev/watch.md)和[健康数据](docs/dev/health.md)。
