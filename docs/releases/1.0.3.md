# TicBox 1.0.3

手机 App、手表 Local Bridge 和内置的 Magisk 模块统一为 1.0.3（versionCode 4）。

## 改进

- 健康数据同步更快。1.0.2 的一次全量同步约 191 秒，其中约 123 秒花在蓝牙传输上（约 80 KB/s），这一版从三处缩短：
  - 手表压缩每页回复（zlib），健康数据的传输量预计减少到原来的几分之一；
  - 每页的确认随下一页的请求一起发出，每页少一次来回，只有每张表的最后一页单独确认；
  - 手表发出一页后，在它传输、手机入库的同时先读好下一页。
- 诊断的“上次同步耗时”和 `run_timing` 日志里，read 的字节数是压缩后的实际传输量；手表预读的时间不算进 watch。

## 修复

- 健康变更日志页：读取状态失败时，“读取状态”一行显示“没能从手表读到日志的状态”，不再显示只适用于开启或关闭的“没能确认结果，已重新读取状态”。
- 变更日志操作失败时，手机和手表都会记录原因：手机写 `journal_result` 诊断（结果和耗时），手表记录 root 辅助进程失败的步骤、异常类型、超时和退出码。读取方法见[健康数据 · 排查](../dev/health.md#6-排查)。

## 升级

1. 用 ADB 安装新的手机 APK：`adb install -r ticbox-phone-1.0.3-release-<commit>.apk`，数据保留。
2. 在本地桥接页更新手表上的 Local Bridge。压缩、随请求确认和预读需要手机和手表都是 1.0.3；只更新其中一边时按原来的方式同步。

## 未在真机验证

- 压缩后的实际传输量和同步耗时，随请求确认和预读在真实蓝牙连接上的表现。
- 变更日志页的新提示，以及失败时两边日志的内容。
