# TicBox 1.0.1

手机 App、手表 Local Bridge 和内置的 Magisk 模块统一为 1.0.1（versionCode 2）。

## 修复

- 手表上的 root 辅助进程改为在全局挂载空间中运行（`su --mount-master`）。此前它们沿用 Local Bridge 自己的挂载空间，看不到官方应用的数据目录，因此：
  - 健康变更日志无法启用，页面显示“数据源不在手表上”；
  - 开启了 root 运动采集也始终没有训练明细，且没有报错；
  - 手表上手动导出的运动快照失败。

## 改进

- 本地桥接页：Local Bridge 已安装但没有响应时，页面顶部会提示在手表上打开它并开启“允许手机读取”，并提供“再次检查”。新装的 Local Bridge（无论从手机还是电脑安装）默认是关闭的。手机安装成功后的提示也说明了这一步。
- README 和发布说明补充了用 ADB 安装手机 APK 的方法。
- 诊断的“上次同步耗时”把 read 拆成手表处理（watch）和传输（transfer），并显示收到的数据量。每轮同步结束时把完整耗时写进日志，可以用 `adb logcat -d -s TicBoxProtocol:I | grep run_timing` 一次读出。

## 升级

1. 用 ADB 安装新的手机 APK：`adb install -r ticbox-phone-1.0.1-release-<commit>.apk`，数据保留。
2. 在本地桥接页更新手表上的 Local Bridge，开关和设置保留；手表模块页会提示原地升级模块。
3. 如需变更日志，在“健康变更日志”页重新开启。
4. 开启了 root 运动采集时，更新后的第一次同步会开始读取训练明细，可能比平时久。

## 未在真机验证

- `--mount-master` 修复后，变更日志的启用与消费、root 运动采集读到非空的训练（需要真实的 Magisk 环境）。
- 本地桥接页顶部的开启提示。
