# TicBox 1.0.11

手机 App、手表 Local Bridge 和内置的 Magisk 模块统一为 1.0.11（versionCode 12）。

## 改进

- **变更日志页打开得更快。** 原来要 5~8 秒：页面依次读健康库和运动库的日志状态，每读一个都要唤醒手表、建一次蓝牙连接，手表再各启动一次 root 辅助进程（每次约 2 秒）。现在：
  - 两个来源共用一次连接，少一次唤醒和连接，第二次连接也不会再因为手表还没关完上一个读取窗口而重试；
  - 健康库的状态经进程内模块读取，不启动辅助进程，这一栏约 1 秒就出来；
  - 运动库的状态仍要启动一次辅助进程，约 2 秒。

  估计整页约 3 秒。没有装模块，或者模块读取出错时，健康库照旧用辅助进程。

- **全量同步每页更快（估计）。** 1.0.10 在真机上读数据点每页 0.73 秒，比 1.0.9 的 0.67 秒还慢。日志显示，预读、写确认和组批三件事是首尾相接的：本地账本同一时间只允许一个写入者，预读每页写账本约 0.3 秒，回复之后写确认要等它提交；组批要等确认；预读已经领先两页，又要等组批才接着读。现在：
  - 预读最多领先四页，不再等每一批组好；
  - 账本的查询挪到写事务之外，写事务更短，确认和组批等得更少；
  - 发送已经组好的批次时不再把上千行解析一遍再重新输出（原来每页约 90 毫秒）。

  估计每页约 0.5~0.55 秒，全量约 14~15 秒。
- **手表日志写明版本。** `Local Bluetooth read window opened` 带上 Local Bridge 的 versionCode；`Local changes sent` 加上写出回复（`write`）和写入确认（`ack`）各用的时间。

## 升级

1. 用 ADB 安装新的手机 APK：`adb install -r ticbox-phone-1.0.11-release-<commit>.apk`，数据保留。
2. 在本地桥接页更新手表上的 Local Bridge。

两边都要更新：共用连接在手机上，经模块读状态在手表上，只更新一边只得到那一半。Magisk 模块的代码没有变化，只是版本号跟着变了，不更新也不影响。

## 未在真机验证
