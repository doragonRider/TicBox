# TicBox 1.0.8

手机 App、手表 Local Bridge 和内置的 Magisk 模块统一为 1.0.8（versionCode 9）。

## 改进

- **通知声音和振动控制默认开启。** 原来要在模块页显式开启：开启时写入启用标记，没有标记就不加载。现在反过来，只有关闭才写记录（`notification-alerts.disabled`），没有记录就加载。
  - 第一次安装模块时，模块页的开关默认开着，安装、开启和重启一次完成。
  - SystemUI 没有保存过模式时，扩展加载后直接按 `ALL` 生效，不再先停在 `OBSERVE`、等页面切换。保存过的模式照旧使用。
  - 安装前在模块页关掉开关，记录会在安装后写进新副本，再重启，扩展不会加载。
- **安装或更新模块和开关通知控制只需一次重启。** 更新前关掉的，更新后仍然关闭；更新前开着的，更新后仍然开着。如果扩展加载后还停在 `OFF`，页面会自动切到 `ALL` 一次。

## 修复

- **更新模块后通知控制不再变成关闭。** 1.0.7 的启用标记要靠安装脚本复制到新副本，这次在一块手表上更新后标记没了，开关变成关闭，原因没有查清。现在默认开启，没有需要复制的东西；关闭记录有三层保留：
  - 安装脚本把旧副本里的关闭记录复制到新副本，安装输出会说明是否保持关闭；
  - Local Bridge 安装前先记下有没有关闭记录，Magisk 安装完成后新副本里没有就补上。即使更新已经暂存、重启前才关闭、又再更新一次，也能保留；
  - 模块页的开关关着时，安装或更新后、重启前再写一次。后两层没写成时，都停在重启之前。

## 行为变化

- **从 1.0.7 升级后，通知控制默认开启。** 旧版关闭时删除启用标记，不会留下关闭记录，所以升级后不再区分“开过”和“关过”，都会加载。需要关闭的话，升级后在模块页关一次。
- 旧版在页面上关闭过的手表，SystemUI 保存着 `OFF` 模式。升级后扩展虽然加载，仍按 `OFF` 委托官方实现；通过模块页的更新流程升级时，页面会在重启后切到 `ALL`。
- 用命令行开关时，命令也反过来了：关闭是创建 `notification-alerts.disabled`，开启是删除它，见[通知的声音与振动 §3.3](../spec/notification-alerts.md#33-开关与模式)。旧的 `notification-alerts.enabled` 不再读取。
- 加载器把这个名字下的任何条目都当作关闭，包括符号链接和目录；查看失败（不是“不存在”）也按关闭处理。

## 诊断

- 原生引导层（日志标签 `TicBoxHealthModule`）不加载 SystemUI 扩展时报告 `alert_opted_out`，查看关闭记录失败时报告 `alert_opt_out_unreadable`，替代原来的 `alert_opt_in_absent`。
- 模块安装输出中的 `Notification sound and vibration control stays off` / `is on` 说明更新后的状态。
- Local Bridge 没能把关闭记录带进新副本时，安装报告 `module_alerts_off_not_kept`。

## 升级

1. 用 ADB 安装新的手机 APK：`adb install -r ticbox-phone-1.0.8-release-<commit>.apk`，数据保留。
2. 在本地桥接页更新手表上的 Local Bridge。
3. 在模块页更新 Magisk 模块，按提示重启手表。

先更新 Local Bridge 再更新模块，关闭记录才有第二层保留；不过从 1.0.7 升级时还没有关闭记录，顺序不影响结果。

## 未在真机验证

- 原生加载器在 SystemUI 启动时对 Zygisk 模块目录执行 `fstatat`：记录不存在时应得到 `ENOENT`。如果 SELinux 让它返回别的错误，扩展会一直不加载，日志会出现 `alert_opt_out_unreadable`。
- 页面用模块目录的修改时间判断这次开机是否已经加载过。如果 Magisk 或别的东西在开机后改动这个目录，页面可能把“需要重启”误报成“重启后没有加载”。
- 一次重启后，安装、开关和自动切到 `ALL` 是否都在真机上完成。
