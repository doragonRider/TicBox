# TicBox 1.0.14

手机 App、手表 Local Bridge 和内置的 Magisk 模块统一为 1.0.14（versionCode 15）。

## 改进

- **步数卡片和步数页面围绕步数目标重新设计**，参考了 Pixel Watch 上 Fitbit 的做法。
  - 健康页的步数卡片显示还差多少步，达标时显示“已达成目标”，下面是一条朝目标填充的进度条。不知道目标时仍显示图表，改为按小时、圆角的柱子；原来每半小时一根细柱，挤成一团。
  - 步数页的“日”视图：顶部是朝目标填充的圆环，中间是当天步数，下面写目标和还差多少；接着是当天的距离、热量和运动时长。图表和列表改为按小时，图表上方默认显示最活跃的一小时。半小时记录的最低和最高值意义不大，已经去掉。
  - “周”视图：用虚线标出目标，在左侧刻度栏标注目标值；没达标的那天柱子颜色较浅；标题下写“7 天中有 N 天达标”。
  - 所有柱状图改为圆角柱子。只有点选某一根时，其他柱子才变淡；原来默认选中最后一根，其他柱子一打开就是淡的。
- 目标用的是本应用里设置的步数目标，没有设置时用手表自己的目标。
- 按小时汇总从当天零点起算，夏令时切换那天有 23 或 25 个小时。

## 修正

- **从远程屏幕的“高级”设置返回时，可能多打开一次画面流。** 几个输入（页面是否可见、画面、设置等）各自送到合并处，返回时“页面可见”可能先于“旧画面已移除”送到，于是在旧画面上打开一个马上又关掉的流。现在任何一个输入变化，都重新读取全部输入的当前值。CI 上 `:ui:testReleaseUnitTest` 偶尔因此失败（`comingBackFromAdvancedResumesTheMirrorWithTheNewSettings`）。

## 升级

1. 在手机上打开新的 `ticbox-phone-1.0.14-release-<commit>.apk` 安装，数据保留。Play 保护机制提示“App scan recommended”时，可以扫描后安装，也可以选择“More details”→“Install without scanning”。用电脑的话运行 `adb install -r`。
2. 手表上的 Local Bridge 和 Magisk 模块只是版本号跟着变了，不更新也不影响。
