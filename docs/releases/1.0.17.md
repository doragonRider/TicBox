# TicBox 1.0.17

手机 App、手表 Local Bridge 和内置的 Magisk 模块统一为 1.0.17（versionCode 18）。

## 改进

- **照片表盘可以编辑了。** 在“手表 → 表盘 → 照片表盘”里选择照片后，会打开新的“编辑照片”页面；“编辑照片和布局”按钮也可以打开它，用的是这次打开页面后编辑过的照片，没有的话就用手表上现有的照片。
  - **移动、缩放和裁剪：** 在圆形取景框里拖动照片、双指缩放，双击铺满屏幕。所选区域可以超出照片，超出的部分是黑色，所以横图、竖图也能完整放进表盘。框外的四角在手表上看不到，会调暗。
  - **按手表屏幕的分辨率发送：** 支持的手表都是 466 × 466，页面上会显示所选区域有多少像素。
    - 比屏幕大时提示会缩小，可以选双线性、双三次或 Lanczos-3（默认）。
    - 比屏幕小时警告会放大、可能发虚，同样可以选三种算法，默认双三次。
    - 缩小时每个像素都参与计算，细节不会因为跳过像素而出现锯齿或摩尔纹。
  - **输出锐化：** 缩放之后可以选“轻”“中”“强”三档锐化。照片停下来后，取景框里显示的就是最终要发送的图，可以直接看出算法和锐化的效果。
  - **表盘布局：** 照片表盘自带的三项设置现在都能改：时间放在顶部、中部还是底部；是否在时间上方显示日期和星期；是否在底部显示电量。取景框和照片表盘页面上的预览会按选择显示时间、日期和电量的位置。
  - 照片以 466 × 466 的 PNG 发送。手表收到后会自己再存成质量 90 的 JPEG，发无损的 PNG，照片就只被压缩这一次。以前是从中间裁成正方形，缩到 480 × 480，再存成质量 80 的 JPEG 发送。
- 读取照片时按拍摄方向转正，并统一转成 sRGB。特别大的照片按长边 4096 像素读入。

## 升级

1. 在手机上打开新的 `ticbox-phone-1.0.17-release-<commit>.apk` 安装，数据保留。Play 保护机制提示“App scan recommended”时，可以扫描后安装，也可以选择“More details”→“Install without scanning”。用电脑的话运行 `adb install -r`。
2. 手表上的 Local Bridge 和 Magisk 模块这次没有变化，只是版本号跟着变了，不更新也不影响使用。

## 未在真机验证

- 发送三项布局设置后，手表上的时间、日期和电量是否在预览所示的位置。各字段的含义和预览的坐标来自原厂 App 的预览，没有对照手表核对。
- 手表会把照片重新存成 JPEG、按 400 × 400 的设计坐标铺满绘制，这些都还没在真机上核对。铺满绘制这一步是直接画到 466 × 466 的屏幕上，还是先缩成 400 × 400 的位图再放大，还不清楚。如果是后者，所选的缩放算法和锐化效果会打折扣。
- PNG 比原来的 JPEG 大得多（通常几百 KB），通过蓝牙发送要多花几秒。
- 在真实手机上拖动和缩放的流畅度，以及停下后生成最终图片的速度。只在 Robolectric 里跑过，照片很大时生成可能要一秒左右。
- 编辑手表上现有的照片：那张图是手表返回的预览，比屏幕小，所以总会提示放大。
